## 1. Frozen sources stay frozen

RF00's originals live under `docs/analytics/editions/legacy/2026-11-12/` (15 studies + `manifest.json` with 72 pinned asset hashes). This slice **did not edit a single frozen byte**: identity, evidence status and publication year live in code, not in their frontmatter.

- The `analytics` collection keeps `glob({ pattern: "*.md" })`, which is single-segment, so the `editions/**` tree can never be globbed into the live series route.
- A new `analyticsEditions` collection uses `glob({ pattern: "editions/*/*/*.md" })` and the same frontmatter schema, so the archive can render the originals with the existing shell.

## 2. One register drives identity and status

`app/src/components/studies/lib/edition-registry.ts` (pure) holds:

| Field | Meaning |
| --- | --- |
| `seriesSlug` | the `/analytics/<slug>` entry the edition belongs to |
| `editionId` | frozen identity, `legacy-2026-11-12`; never reused |
| `publicationYear` | archive path year, or `null` → `undated` |
| `evidenceStatus` | `approved` \| `historical` \| `withheld` |
| `editorialStatus` | `published` \| `draft` \| `archived`, kept separate from evidence |
| `frozenSource` | repo-relative path, shown on the archive page |
| `assetsPinned` | referenced data/figure assets pinned at freeze |

`validateEditionRegistry()` returns *every* problem at once — duplicate `(series, edition)`, reserved segments (`archive`, `personas`), malformed slugs, impossible years, bad asset counts — and the archive route refuses to build if the register is invalid.

**Current-versus-archived rule:** `approvedEditionFor()` returns the newest edition whose status is `approved`, never the newest by date. With no such edition today, every series renders "No approved current edition" and links its frozen edition. A test proves an older approved edition wins over a newer unapproved one.

## 3. Archive route

`/analytics/archive/<year>/<edition>/<slug>` — 15 routes generated (`219` pages total, up from `204`).

- Header and status panel carry the edition identity, publication year, editorial status, evidence status, frozen source path and pinned-asset count.
- `data-edition-status` is a stable hook (`historical`, `withheld`, `approved`) for tests and future filters.
- The status panel links back to the current series entry.
- One `<h1>` per page: the shell owns it and the global remark plugin strips the frozen article's leading H1.
- **Gates carry over:** a study whose units are under review (`lease-decay`) keeps its charts withheld on the archive URL too, and no chart island is mounted — an archive path cannot revive a withheld chart (RF07 §6).
- The archive route throws at build time if a frozen file has no registered identity, so an unreviewed page can never be emitted.

## 4. Series entry

`/analytics/<slug>` gains an edition panel:

- approved edition when one exists;
- otherwise "No approved current edition", explaining that a refreshed edition needs independent sign-off, plus a link to each archived edition with its evidence and editorial status.

Editorial `status` from the frozen frontmatter is still shown in the header badge, separate from the evidence panel — publication status is not evidence status.

## 5. Tests

- `tests/unit/edition-registry.test.ts` (9 tests): the register matches the frozen directory exactly (drift guard), every `frozenSource` exists, the register validates, no series claims an approved edition, approved-over-newer selection, archive paths (including `undated`), and rejection of reserved slugs, duplicates and malformed identities.
- `tests/e2e/analytics/archive.spec.ts` (4 tests): identity/status/source rendering and one H1, the series-entry link round trip, withheld charts on the archive, and a sample of archived routes loading without page errors.

## 6. Not in this slice

| Item | Why / next owner |
| --- | --- |
| RF08 refreshed editions | Each job needs three recorded sign-offs, including a scientific reviewer who did not author or fit the result (D12). No refreshed numbers were invented. |
| Persona-card evidence status | Persona pages list series cards; the status currently reaches them only via the series page. Propagating `evidenceStatus` into `StudyCardData` is the RF08/RF10 follow-up once an approved edition exists to display. |
| Archive index / filters | The route pattern is stable and linkable; a browsable index with edition/year/evidence filters is a UI increment, not a contract requirement. |
| Library card edition ids | One card per series is kept, as RF07 §5 requires; edition ids appear on the series and archive pages. |
